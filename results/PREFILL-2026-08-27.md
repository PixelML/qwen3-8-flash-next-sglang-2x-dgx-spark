# Uncached prefill results — 2026-08-27

## Result

The production-shaped headline is **2,960.12 input tok/s at a 16K prompt**.
Shorter prompts carry a larger fixed HTTP, tokenization, scheduling, and
first-token cost:

| Target prompt | Median actual prompt | Median TTFT | Median input tok/s | Three-run range |
| ---: | ---: | ---: | ---: | ---: |
| 1K | 1,046 | 0.4524 s | 2,327.78 | 2,281.64–2,384.69 |
| 4K | 4,103 | 1.4924 s | 2,758.65 | 2,622.26–2,959.58 |
| 16K | 16,471 | 5.5729 s | **2,960.12** | 2,940.77–2,960.96 |

These numbers measure one uncached request at a time. They are not continuous
batch throughput and should not be compared directly with aggregate decode TPS.

## Method

- Hardware/runtime: the exact two-DGX-Spark TP=2, NVFP4, NEXTN/MTP profile in
  this repository.
- Each request uses a unique randomized prefix, `reasoning_effort=low`,
  `temperature=0`, streaming, and exactly one requested output token.
- The API's returned `prompt_tokens` count is divided by time to first content
  or reasoning token. This includes HTTP, tokenization, scheduling, and first
  decode, so it is a conservative client-observed prefill rate.
- Each target is calibrated to within about 5%, warmed once at the calibrated
  size, then measured three times. The table reports medians and full ranges.
- Final run seed: `1787817837526157387`. All 50 server-side prefill batches in
  the final run window reported `#cached-token: 0`.

SGLang uses 4,096-token chunked prefill in this profile. Its per-chunk
`input throughput` log field is instantaneous and can spike on small tail
chunks, so this report deliberately uses end-to-end TTFT rather than publishing
those misleading peaks.

## Reproduce

From rank zero after the authenticated API is ready:

```bash
python3 scripts/prefill-benchmark.py
```

The default seed is fresh on every invocation to prevent accidental radix-cache
reuse. Pass `--seed <integer>` only when the server cache has been cleared or
the model has restarted.
